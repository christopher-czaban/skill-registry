# Security policy

## Reporting a vulnerability

Please report suspected vulnerabilities through the repository's GitHub
private security advisory workflow. Do not open a public issue containing an
exploit, credential, private registry content, or other sensitive evidence.

Include the affected version, platform, reproduction steps, impact, and any
suggested mitigation. Maintainers will acknowledge the report through the
private advisory and coordinate validation and disclosure there.

## Supported versions

Before the first stable release, security fixes are made on the current
development line. Release support policy will be documented when stable
versioning begins.

Skill Registry deliberately treats destination ownership, root resolution,
rollback, and deployment records as security boundaries. Reports involving
path substitution, symlink traversal, destructive replacement, source
confusion, or release-workflow permissions are especially valuable.
